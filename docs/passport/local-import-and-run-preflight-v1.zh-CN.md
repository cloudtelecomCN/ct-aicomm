# 本地导入与运行预检 v1

状态：CT-610 公开工作契约。版本：`1.0.0`。

CT-610 在链路证据护照的计划运行与 `started` 状态之间加入强制的本地导入和预检门禁。
预检失败、过期、引用不一致或缺失时，运行不能启动；每次被拒绝后，原计划仍保持不可变的
`planned` 状态。

## 契约

1. [`local-run-import-v1.schema.json`](../../specs/passport/local-run-import-v1.schema.json)
   将精确的计划运行、场景方法冻结与本地载荷指纹绑定。
2. [`run-preflight-v1.schema.json`](../../specs/passport/run-preflight-v1.schema.json)
   记录五项门禁输入、确定性结果、阻断原因和新鲜度截止时间。
3. [`index.mjs`](../../packages/link-evidence-passport/index.mjs) 提供零依赖参考评估器和唯一的
   公开启动转换。

本地导入只接收调用方已经放入内存并完成解析的对象，不访问文件或网络，也不会保留源路径、
原始载荷或凭据。`payload_fingerprint` 在不公开本地包内容的情况下标识调用方提供的载荷。

## 五项强制门禁

| 门禁 | 通过条件 |
|---|---|
| 授权 | 精确租户、执行人、动作、运行和冻结版本均获允许；授权已生效、未撤销，并覆盖完整计划窗口。 |
| 时钟 | 时钟检查已同步、仍新鲜，且观测偏差不超过声明上限。 |
| 预算 | 租户和运行引用一致，预计最小货币单位成本不超过未占用额度，预算有效期覆盖运行窗口。 |
| 并发 | 租户和运行引用一致，带来源指纹的新鲜并发快照仍能容纳全部申请槽位。 |
| 停止条件 | 必须具备安全的最长时长、最大失败数和预算耗尽硬停止规则。 |

可预期的运营失败会形成不可变的 `decision: "failed"` 预检记录，而不是伪装成格式错误，
也不会改变运行状态。稳定阻断码包括 `authorization_denied`、`clock_skew_exceeded`、
`budget_exceeded`、`concurrency_exceeded` 和 `stop_condition_unsafe`。

## 新鲜度与启动不变量

评估器从以下时间中自动取最早值作为 `valid_until`：

- 计划运行结束时间；
- 授权到期时间；
- 预算到期时间；
- 时钟检查新鲜度截止时间；
- 并发快照新鲜度截止时间。

`startPassportRun()` 必须同时收到精确的计划、冻结、本地导入和已通过预检；其中的租户、
版本和内容指纹必须全部一致，调用方还必须声明与预检授权相同的执行主体。启动时刻不得早于
预检评估时刻，也不得晚于 `valid_until`。
公开 SDK 不提供绕过预检的启动入口。因此，预检失败不能进入“已运行”或 `started` 状态。

## 完整性与授权边界

所有记录采用确定性 SHA-256 内容指纹和封闭对象，可发现意外或恶意修改，但内容指纹不是身份
签名。生产宿主必须先认证执行人并验证授权来源，再向本契约提供来源指纹。公开契约不会访问
授权服务、预留资金、占用运行槽、执行基准、签发认证或作出性能声明。

公开仓库只包含 Schema、评估器、类型声明、文档和合成示例。真实授权、客户身份、端点地址、
预算、凭据和运营快照仍保留在获授权的私有系统中。

## 离线示例

```bash
node examples/passport/local-import-preflight-synthetic.mjs
```

示例生成一个通过预检和一个预算失败预检。只有通过记录可以启动合成运行。示例不需要凭据，
不访问外部网络，并明确禁止性能与认证结论。
