# 链路证据护照：场景与方法冻结 v1

[English](scenario-and-method-freeze-v1.md)

状态：CT-609 公开工作契约。版本：`1.0.0`。

## 目的

链路证据护照在展示结果之前，必须先说明一次运行试图回答什么问题。CT-609 将这个问题
冻结为一条受内容指纹保护的记录：

- 恰好一个源站点和一个目标站点；
- 流量方向；
- 精确的协议标识、版本和可选 profile；
- 工作负载类别、名称、精确版本、来源和配置指纹；
- 精确版本的 Evidence Core Scope 和 Method；
- 方法工具、工具制品、参数、采样计划、预热数量、排除规则、统计项和环境前提。

冻结记录让无声的参数漂移可见，但不会证明站点、方法、工作负载或后续测量真实有效。

## 记录

契约发布两个严格的 Draft 2020-12 JSON Schema：

1. [`scenario-method-freeze-v1.schema.json`](../../specs/passport/scenario-method-freeze-v1.schema.json)
   描述受保护的场景和方法模板。
2. [`run-freeze-binding-v1.schema.json`](../../specs/passport/run-freeze-binding-v1.schema.json)
   将一个精确运行版本绑定到一个精确冻结指纹。

两者都拒绝未知字段和浮动的 `latest` 版本。规范化内容使用 SHA-256 保护；所有引用都受
租户范围约束并固定到精确语义化版本。

## 运行规则

生命周期有意保持收敛：

1. 创建并验证一条场景方法冻结记录。
2. 创建绑定其精确指纹的 `planned` 运行记录。
3. 通过新的绑定版本启动运行，状态变为 `started`，规范 UTC `started_at` 必须位于计划窗口内。
4. 后续每个场景或方法候选都与已启动运行的冻结指纹比较。
5. 任一受保护字段变化时，返回 `passport_new_run_required`。
6. 创建不同的 `run_id`，引用已启动的前序运行，并把新运行绑定到变更后的冻结记录。

变更参数后复用旧 `run_id` 会被拒绝，旧运行保持不变并可供复核。新运行也可以有意复跑
相同冻结记录；本规则阻止隐藏变更，不阻止合法重复。

## 受保护变更示例

以下任一变化都会改变冻结指纹：

- 任一站点、站点角色、地域或方向；
- 协议标识、精确版本或 profile；
- 工作负载类别、名称、版本、来源或配置指纹；
- Scope 或 Method 的对象身份或版本；
- 工具版本或制品指纹；
- 任一参数值或单位；
- 样本数、间隔、预热数、排除规则、统计项或环境前提。

数组在计算指纹前会规范排序，因此仅重新排列相同参数不会被视为实质变更。重复站点身份、
参数名、规则 ID、统计项和环境前提都会被拒绝。

## 与 Evidence Core 的关系

CT-609 不替代 Evidence Core 的 `Scope`、`Method` 或 `Run` 对象，而是在精确 Scope 和
Method 引用外增加护照专用冻结和运行绑定。CT-610 后续可以加入授权、时钟、预算、并发和
停止条件预检证据，而不重新定义已经冻结的问题。

## 公私边界

Schema、参考实现、类型声明、文档和合成场景公开。真实租户身份、客户拓扑、端点地址、凭据、
原始观测和运营运行状态仍保留在获授权的私有系统中。未来的公开护照必须使用单独派生的公开
投影，不能直接发布本租户范围记录。

本契约不访问网络，也不会：

- 启动流量或执行基准测试；
- 认证身份或授权运行；
- 验证测量来源或环境；
- 确认与另一运行可比；
- 允许性能声明；
- 签发独立复核或认证。

## 运行合成场景

```bash
node examples/passport/scenario-method-freeze-synthetic.mjs
```

该场景在运行开始后修改目标样本数，验证稳定错误 `passport_new_run_required`，拒绝复用原
`run_id`，并创建替代运行计划。它不访问外部网络，不包含生产端点、客户数据或实测结果。
