# 证据导入与幂等契约 v1

[English](import-and-idempotency-v1.md)

状态：CT-604 公开契约。本契约把一个经过外部锚点确认的 CT-603 包导入租户
范围的身份台账，但不把对象原文复制进台账。

## 验证顺序

一次导入只有依次通过以下闸门才会提交：

1. 有效的尝试元数据和租户绑定的幂等键；
2. CT-603 的字节、对象、内容、manifest 与外部锚点验证；
3. CT-601 对象信封、规范单位和 UTC 时间检查；
4. 单一租户内的精确版本引用闭包；
5. 与已存对象进行不可变身份比较。

生产方必须在导入前使用 CT-601 Evidence Core schema 校验完整对象载荷。CT-604
参考导入器会独立检查作出导入决定所需的精确顶层信封、授权信封、身份、单位、
时间与跨对象语义，并在任何失败时关闭导入。

参考实现不访问网络，也不需要凭据。生产服务仍须负责身份认证、授权、持久
事务、保留策略和租户隔离。

## 单位

Observation 数值和 Method 数字参数使用版本化的规范单位目录
`EVIDENCE_CANONICAL_UNITS`。v1 接受：

`1`、`bit/s`、`byte/s`、`bytes`、`count`、`ms`、`ns`、`percent`、
`request/s`、`s`、`token/s` 和 `us`。

`Mbps`、`%`、`milliseconds` 或本地化文本等别名不会被静默转换。生产方须在
导入前换算数值并声明规范单位；非数字 Method 参数使用 `null`。

## 时间规则

所有时间必须精确使用 UTC 表示，例如 `2026-10-23T00:01:00.000Z`。创建、
观测、实际运行、封存、复核和决定时间不得晚于 `received_at`。授权到期、
Scope 有效期和计划窗口可以在未来，但起止和到期顺序必须合法。Observation
必须落在其精确引用的 Run 实际窗口内。

## 引用闭包

每个引用必须固定对象类型、ID、SemVer 和租户。浮动、缺失、类型错误和跨租户
引用都会被拒绝。EvidenceVersion 声明的 Scope、Method、Run、Observation 与
Artifact 引用必须与受保护的证据内容集合完全相同，不能多带或漏带对象。

## 幂等与不可变版本

- 同一幂等键和同一请求再次提交时，无论原结果是提交、重放还是失败，都返回
  原记录，不新增尝试或对象。
- 同一受保护内容使用新幂等键时，只新增 `replayed` 记录，不复制对象。
- 同一幂等键对应不同字节时，新增 `rejected` 记录。
- 同一租户、对象类型、对象 ID 和版本对应不同内容时拒绝导入；旧指纹保持
  不变，内容变化必须创建新版本。

## 失败记录

每个可处理的失败都会追加一个严格的 `evidence_import_record`，只保存稳定错误
码和 JSON 风格路径，不保存原始内容或凭据。记录通过
`previous_record_fingerprint` 形成 SHA-256 链。无效尝试 ID 或畸形审计元数据
无法安全入账，因此会在修改台账前直接拒绝。

## 信任边界

提交成功只说明相对于指定外部锚点通过了结构、完整性、语义和不可变身份检查；
不证明内容真实性、测量真实、授权、独立复核、性能有效或认证。每个导入记录
都把这些结论固定为 `false`，权威私有服务必须另行判断。

仓库内场景是合成数据，不代表生产测量。
