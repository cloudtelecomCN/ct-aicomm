# 监督重新运行与环境差异 v1

[English](supervised-reexecution-and-environment-differences-v1.md)

CT-619 记录由指定复核负责人监督的一次后续运行，并把它绑定到一份确定的历史 Passport 交付包和 CT-618 统计复算记录。它强制区分**后续运行**与**历史状态重现**：后续运行可以形成有用证据，但不能因为已知输入相同，就被表述为重现了过去的环境。

## 必需证据链

只有以下输入能够共同通过验证时，系统才创建记录：

1. 复核级别严格为 `supervised-reexecution` 的 CT-616 委托；
2. 基于已声明记录判定为可继续的 CT-617 评估；
3. 仍在有效期内、且明确指定复核负责人和复核机构的 Passport 分享记录；
4. 完整校验过的历史交付包及其不可变运行引用；
5. 与同一委托、评估、分享记录、Passport 和交付包绑定的有效 CT-618 复算记录；
6. 在历史交付和统计复算之后开始的新运行；以及
7. 覆盖整个新运行的实时观察窗口与监督事件日志指纹。

分享权限必须在运行开始、运行结束和记录创建三个时点均保持有效。记录创建者和监督者都必须是指定的复核负责人。

## 七个环境维度

`compareIndependentReviewRunEnvironment()` 从 `freeze.json` 推导历史侧，调用方不能自行提交历史分类。差异登记始终包含以下七个维度，并保持固定顺序：

1. 站点；
2. 协议；
3. 工作负载；
4. 方法；
5. 计算环境；
6. 软件环境；以及
7. 网络环境。

当前快照把每个维度标记为 `observed`、`declared` 或 `unknown`，每个已知值必须提供 SHA-256 指纹。双方已知且指纹相同分类为 `same`，双方已知但指纹不同分类为 `changed`，任一侧缺失则分类为 `unknown`。

当前 Passport 交付包只为站点、协议、工作负载和方法保留了结构化历史数据，没有结构化的计算、软件和网络快照。因此，即使后续运行声明了后三类环境，它们的历史比较仍然是 `unknown`。实现不会把未知历史自动升级为一致。

## 时间语义

每条 CT-619 记录都固定使用 `classification: later-execution` 和 `historical_state_reproduced: false`。即使所有已知维度一致，这一结论也不会改变。时钟、瞬时负载、固件状态、网络条件、依赖项或未记录配置仍可能影响后续运行。

记录保留后续运行指纹、产物清单指纹、监督窗口、事件日志指纹、历史引用、环境差异和派生计数。它不比较性能结果，也不推断性能提升或回退。

## 信任边界

CT-619 记录了监督事实，但不对监督者提供外部证明，不认证所声明主体，不外部核验机构控制关系或导出授权，也不认证复核独立性。它不签发意见，不改变 Passport 状态，不形成性能结论，不裁决 SLA，也不签发认证。

仓库内示例均为合成数据，用于在不需要凭据、客户数据、私有基础设施和外部网络的条件下验证绑定关系与失败行为。
