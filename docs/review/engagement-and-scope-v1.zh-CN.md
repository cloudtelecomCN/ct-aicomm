# 独立运行复核委托与范围 v1

[English](engagement-and-scope-v1.md)

CT-616 定义开展独立复核工作之前必须形成的不可变委托记录。它解决一个常见证据缺口：“复核这个结果”本身过于模糊，必须在工作开始前固定精确证据版本、交付包、复核层级、容差、用途和预期输出。

## 精确证据绑定

每项委托必须引用：

- 一个精确的 `passport_evidence_version`，包括内容指纹；
- 一个通过离线交付包验证的精确 `passport_delivery_manifest`；
- 两项记录共有的租户；
- 委托创建时仍为有效、已封存状态的护照版本。

委托不能静默转向替代护照或其他交付包。因此，证据版本变化必须创建新委托。

## 复核层级

| 层级 | 约定输出 | CT-616 实际证明的内容 |
|---|---|---|
| `structure-only` | 范围记录和结构检查清单 | 只证明已委托结构复核 |
| `statistical-recalculation` | 结构输出、复算报告和差异登记 | 只证明已委托统计复算 |
| `supervised-reexecution` | 复算输出、监督运行引用和环境差异 | 只证明已委托未来监督重跑 |

层级决定必需交付物。CT-616 本身不会生成这些发现或结论。

## 容差与用途

容差必须明确：

- `exact` 不允许任何容差规则；
- `declared-thresholds` 必须给出一个或多个指标、单位、比较方式和阈值规则。

用途包含预定用途分类和有边界的说明。每项委托都明确禁止把结果用作认证、法律结论、性能保证、生产控制授权或 SLA 裁决。

## 交付约定

约定固定截止时间、交付模式、格式、语言和与层级对应的交付物。记录不包含 bearer secret 或制品原文；受限证据访问授权仍是独立决策。

## 范围替代规则

下列字段共同构成不可变范围：

1. 护照引用。
2. 交付清单引用。
3. 复核层级。
4. 容差策略。
5. 用途。
6. 交付约定。

任何范围变化都必须创建新委托。替代委托必须使用不同的 `engagement_id`，引用上一委托的精确内容指纹，说明变更原因，并且至少改变一个范围字段。实现会拒绝复用同一标识修改范围，也会拒绝没有范围变化的替代委托。

## 信任边界

有效委托只表示存在结构完整且带内容指纹的工作约定。它不证明身份、组织关系、利益冲突、复核方独立性、证据访问授权、复核已经执行、意见已经签发、SLA 已违约、性能已证明或认证已签发。CT-617 将增加身份、组织和利益冲突控制；CT-618–620 再增加实际复核工作与受治理意见。

## 离线示例

```bash
node examples/review/engagement-scope-synthetic.mjs
node --test tests/review-engagement-scope.test.mjs
```

示例只使用合成证据，不形成生产性能声明，不需要凭据或外部网络。
