# CT-DataPlane Agent 威胁模型 v1

## 信任边界

Agent 运行在推理主机或明确受管的网关上。控制面、制品仓库、遥测端、Linux 内核和本地运维人员属于不同信任域。策略建议不等于执行授权；只有签名有效、版本递增、目标在白名单中且通过后续 prepare/apply 协议的策略才允许改变路由。

## 权限边界

服务不以 root 身份运行，也不得提权。首版 Linux capability 上限为 `CAP_BPF`、`CAP_NET_ADMIN` 和 `CAP_PERFMON`。禁止 `CAP_SYS_ADMIN`、加载内核模块、进程跟踪和绕过文件访问控制。部署必须启用 seccomp、SELinux 或 AppArmor，并使用只读根文件系统。

如果目标内核不能满足该边界，Agent 只能保持观察模式。扩大权限必须形成新版本威胁模型并经过安全审查；安装过程不得静默降级为 root 或 `CAP_SYS_ADMIN`。

## 供应链与配置

Agent 制品必须具备 SHA-256 摘要、签名、SBOM 和构建来源证明。未签名或签名不匹配时拒绝启动。配置只能来自 root 所有的本地引导文件或双向认证控制面。版本必须单调递增，回滚目标必须曾经成功应用，未知来源一律拒绝。

## 数据与网络边界

禁止采集载荷、Prompt、生成 Token 和凭据。遥测仅允许批准的标识符与测量值，并必须脱敏。网络出口默认拒绝，只允许访问控制面、遥测端和已声明健康探针；Agent 不开放公网监听端口。

## 失败不变量

身份失败、过期策略、非法目标、租约到期、控制面失联、升级失败或 Kill Switch 触发时，Agent 必须保持或恢复最近一次确认正常的路由并产生审计事件，不得自行创造路由或继续未经确认的切换。

机器可读边界和威胁登记位于 [`../../specs/agent/security-boundary-v1.json`](../../specs/agent/security-boundary-v1.json)。
